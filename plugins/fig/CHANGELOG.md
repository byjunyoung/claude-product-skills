## 3.31.0 — 2026-10-20

- **`/fig:read` works from any Figma seat, with no token.** It listed pages through Figma's REST API, which needed a personal access token, so a person without one saw only some pages of a file. It now lists pages with the same read-only `use_figma` call `/fig:setup` already makes, and passes `figma-use` in `skillNames` as that skill requires. The token is still used, by `/fig:handoff` and `/fig:sync`, to read a saved version back. `_common/version-pin.md` step 4 now resolves the variable name through `tools.figma_token_env`, checks it is non-empty before the call (so a 401 means an expired or wrong token, never a missing one), and names the scope the versions endpoint needs, `file_versions:read`; the token setup lines moved there from read, and the key's comment says so
- **`/fig:handoff` finds its task before it asks.** With no task input under `notion` or `github`, it searches the tracker `task_tracker.ref` names (read-only, after the section choice and before the version is pinned), using the file's name and the names of the sections chosen. One hit is named in the preview and carried on; none or several are listed and you pick, and it never picks for you. Before, it said it could not find the page and printed the line. The two search tools (`notion-search`, `search_issues`) are now pre-approved, and nothing else is
- **`/fig:draw` and `/fig:prep` (which now loads `figma-generate-design` before its first mutating call) say which parts of the official `figma-generate-design` skill they use, and obey its rules.** draw takes its component discovery and its way of editing an existing screen, not the page-level wrapper or `html_to_figma`, because draw clones a canonical screen; it names `figma-use,figma-generate-design` in `skillNames` on every mutating call (`figma-use` SKILL.md requires `figma-use` there). prep's "no more than ten operations per call" is replaced by the reason behind it: size a call for safe retry (`figma-use`: do not split a script into checkpoints), because `clone()` and `createFrame` land on the page and a batch that fails halfway leaves orphans. Verification follows a mutation that bears on the next step rather than every split
- **`/fig:code`, `/fig:proto` and `/fig:deck` obey the official skills' must-do lines.** code takes assets from the `get_design_context` response and no longer calls `download_assets`; proto loads `figma:figma-design-to-code` before its first `get_design_context`; deck loads `figma:figma-create-new-file` before `create_new_file`, and says the default light theme is only a skeleton. Each lists `Skill` among its tools so it can load them. These are the official skills' MUST rules, not a preference — except two that proto deliberately does not follow and now says so: it does not re-request a sparse response's children (its labels come from the text walk, and it is a behavioural prototype), and it exports image nodes whole with `get_screenshot` rather than downloading assets as the response describes, so overlays come along and the deliverable stays one file. code obeys the asset line; deck and proto obey the load-first lines
- **Three `/fig:deck` keys are retired and nothing reads them: `deck.template_file`, `deck.fidelity` and `deck.batch_size`.** They are out of `conventions.example.yaml`. A config that still sets them is not an error — they are ignored — and can be deleted whenever convenient. `deck.assets_dir` stays
- **`/fig:qa` says where the report goes, and what it compares against.** The report goes to the response, and, where the new key `qa.report_dir` names a folder, also to a markdown file there after your go; left `null`, no report file is written (captures are saved either way). `qa.baseline.tasks` now takes `{ type, ref }` (`markdown` or `notion`; qa has no GitHub read path), and is skipped where either is `null`. qa reads the design from the live file: the version a handover pinned is not yet compared, so a design edited after handover is judged as it stands now (this is the entry qa's baseline table points to). The "ticket log and reply drafts" qa claimed, which no tool of its own could write, are gone
- Wording: a few sentences the task reviews found no longer true — read no longer claims to run scripts, handoff names the point at which it searches, draw's assembly sentence agrees with its "no wrapper" paragraph, qa's cross-reference uses the heading it names, and the two `pm` sentences that spoke of "the handover line" in the singular now say the last one. Both root READMEs' *What each skill needs* gain handoff's search tools and qa's `qa.report_dir`

## 3.30.0 — 2026-10-19

- **`/fig:lint` can audit one section.** Give it a section link or name and it reads that section and whatever is nested in it, so a fix to one screen group is checked without a whole-page run's noise; a link to a frame reads the section holding it. A name that matches no section, or several, is asked about rather than guessed; an id that is not on the page is a blocking `[section]` finding; a section in `pages.exclude_sections` is left out with a note; a section overlapping its neighbour is still reported, since the overlap belongs to both. Frame membership and order are page-level questions and are skipped, and the structure audit returns a note saying so, which lint prints with every other note
- **`/fig:lint` catches colours not bound to a design-system token, as `[unbound]`.** Before, a hand-typed colour was found only if you ran `/fig:tokens` yourself, so a screen could pass the gate and still stop following the theme. A colour that matches the exact RGBA (opacity included) of a token scoped for that property is blocking, since engineering would copy the hex. This changes what `/fig:handoff` lets through: a section with a colour exactly matching a token scoped for that property is now held back until the colour is bound. A near or no match is a warning, because snapping it changes the colour and that is a designer's call. An exact colour whose only tokens are scoped for other properties — a rectangle's fill matching a text-only token, or a primitive scoped to nothing — is a warning saying so: it is offered the nearest token scoped for its property where one is within the threshold, and otherwise none, since no token can be bound there. Lint and `/fig:tokens` read scopes through one shared block (`token-fit`), so lint never holds a section back for a token the bind would refuse. A colour on a node loose on the canvas, in no section, is a warning whatever it matches, since handoff gates sections. Skipped: colours applied through a style, hidden layers, everything inside a component instance — its layers and the overrides on them — and an instance's own paint except where the instance overrides it, arrows, labels, placeholders, sections' own paints, excluded sections and non-solid paints. Colours inside instances are graded on the page that holds the component's master, so where instances in scope hold hand-typed colours the result carries a note counting them and saying to run lint on that page — a draft component's colours would otherwise go unseen. A file with no colour tokens passes with a note. Library tokens are read through the bindings already on the page, and ones that cannot be resolved are noted rather than guessed. Values are read in each collection's default mode
- **`/fig:tokens` only binds now.** The "lint mode" is gone, since lint does the checking. Its scan lists each colour per kind (fill, text, stroke, effect) with only the tokens scoped for those paints, and the dictionary carries each token's scopes, so the mapping table never proposes a token the bind will refuse. It scans, shows a dry-run preview (writes nothing, imports nothing) listing per node and paint the tokens it would try in order, and binds only what the preview showed, after a go. A change a designer can see — colour, opacity or mode — is skipped unless it was accepted in the preview, so approving one colour no longer binds its neighbours, and every failed import is reported. The bind needs its `DRY_RUN` line stated — `true` for the preview, `false` to write — so a forgotten line throws instead of writing, and the real run returns `changed`, each visible change it made, an accepted change to a token the preview could not read yet included. `design_system.match_threshold_channel` now only decides what counts as near: a near colour is asked about node by node in the preview and is no longer proposed on its own, where before a colour within the threshold was auto-proposed like an exact one. A frame link now widens to the section holding it, since the scripts scope by page or section, and the preview says so; a frame in no section means the whole page, said too. `/fig:draw` drops its separate token check for the same reason: lint covers the colours on the frames drawn — not the ones inside a component instance, which it counts in a note — so draw's last step also runs lint on the page that holds a draft component its screens use
- **Audit scripts return a graded result, `{ pass, findings, note? }`, with each finding `{ tag, grade, node, msg }`.** Lint used to hold the grade table in prose and the scripts only said "found", so the two could disagree without anyone noticing. Lint now reads the grade from the script, the component compare reports properties the collect pass never saw as `unknown` rather than as findings, and a parity test ties lint's table to the scripts' grades. The component script now throws when the page it is pointed at is not found, rather than coming back as if it had found nothing
- **The nested-section walk reaches the component audit, the probe page and prep's section grow.** Frames inside a sub-section were audited by structure and flow but skipped by component, observed by neither probe nor setup's draft, and prep's resize looked only at the top level. `pages.exclude_sections` is honoured in both component modes; probe takes a `depth`; setup counts numbered-section evidence on depth 0 and proposes exclusions from any depth, so an archive nested under a section is offered too. `verify` now compares every marked block (`sections-deep`, `scaffolding`, `scope-of`, `paint-scope`, `token-fit`) across the scripts and names both files on a mismatch, where it used to compare one
- **`[state]` dashed links are measured on x as well as y.** A link that leaned sideways passed because only the vertical was checked. An arrow-build to audit-flow round-trip test now confirms an arrow the build skill draws passes the audit, so the two cannot drift apart
- **Code that lived in skill text is now scripts with tests.** `/fig:sync`'s comparison and edits are `sync-compare.js` and `sync-ops.js` (keyword search, structure pairing, `editValue`/`editValues`, which load every font before the first write so a failure cannot leave a half-edited screen, and a four-edge clearance check that measures a section against the sections beside it — its parent's, so a nested section is no longer measured against the one holding it); `/fig:proto`'s text walk and image-fill search are `text-walk.js` and `image-fills.js`. Both take an optional `ROOT_ID` — the frame, section or page to read, the current page when left out — and read the node on its own page. The text walk's result changed shape: a bare array `[{ id, text, x, y, hidden }]`, top to bottom, where the inline snippet returned `{ form: [{ y, x, t, h }] }`. Snippets copied out of a document by hand were the one place a fix could not be tested; the tests now run against the script files themselves
- Guard: `tools/test/verify.test.py` gains a case that a 750-character deck description fails even under its 700 override. `verify` already failed it; the case keeps it that way
- Wording: both root READMEs and the plugin README describe lint as four groups (structure, flow, components, colours) and list the section input and the sideways state link; lint's own `[state]` row names the sideways check too. The repository tree lists the new scripts and the `draw` and `sketch` skills it had left out, and the glossary's "token" covers both senses the READMEs use — the access key and the design system's named colour

## 3.29.0 — 2026-10-19

- **`/fig:diff` is gone.** It generated an AS-IS/TO-BE table into the task doc, and nobody read the table. Nothing replaces that written record, on purpose. For looking at what changed, Figma's Dev Mode has *Compare changes*, within its limits: it needs a Dev Mode seat, and it compares a frame with its own version history (or two components with each other), not two separate frames. Both root READMEs map `/fig:diff` to this note, so someone typing the old name finds where it went
- **`/fig:handoff` carries the Notion and GitHub writes itself, which it used to borrow from `/fig:diff`.** In a Notion page the line goes into the `ui_section_heading` section after the last hand-over line already there, or, in a section with none yet, right after the heading and whatever block opens it (no callout assumed); a GitHub issue body is written the same way, or a comment is added where the body has no such section. The lines read oldest to newest, as in a markdown task file. Without a `task` input under Notion or GitHub it prints the line and says why, since it cannot search the tracker for the task itself
- **`/fig:deck-setup` is folded into `/fig:deck`; measuring the slide template is now its first step.** Two skills for one job meant a deck request on a new machine failed with "run the other one first". `/fig:deck` now measures the template on first use, or when you say it was revised, and carries on into the deck — the steps live in `deck/setup.md`, the trap list in `deck/pitfalls.md`. Every trigger phrase `/fig:deck-setup` answered to, apart from its old command name ("extract the slide template", "발표 템플릿 추출" and the rest), now starts `/fig:deck`. The Figma writes of the measuring step are gated: the mirror Slides file it creates and the verification slides it builds each get a preview and a go, after a `whoami` check that the seat can write, and the final report names the mirror file. `pitfalls.md` points at the installed `figma-use-slides` where that skill states the fix, and keeps its own text only for what is specific to this template
- **`/fig:sync` compares each working frame with the canonical frame of the same name.** The first signal is a direct text comparison with the canonical twin, replacing the pairing of whole sections by name patterns. Which side a difference sits on decides the bucket. Text only the working frame has, missing from canonical, is not applied. Text only canonical has may be later work that landed there since, so on its own it is graded needs checking, and the apply step's preview lists every such string it would remove for a confirm — on archive and queue pages alike — instead of removing it silently; the person confirms or declines each frame as a whole, and a declined frame keeps its text and stays in its bucket. Identical text counts as applied only when heights and component masters match too; where either differs, the frame goes to needs checking, since neither says which side moved, and a frame confirmed for that difference is moved rather than value-edited. A visual-only change inside the same height and components is seen by no signal, and the report and the archive preview say so. Every string is compared whatever its length: `sync.text_diff_max_len` used to drop longer strings from the comparison, which let a long notice be removed without being listed, and now only shortens how a long string is shown. Names are matched by the file's own `naming.frame_pattern`: a name that fails it is asked about, pointing at `/fig:prep`, and with no pattern set frames pair by exact name. A frame with no twin is reported as new; duplicate canonical names and a canonical frame with no working twin each have a stated place in the result; sections in `pages.exclude_sections` are skipped on the canonical page as on the working one, so a reference copy does not make a screen ambiguous. Its config write (a page choice recorded under `files.<fileKey>`) now shows the exact block, the file and a choice of layer — personal or project, and whether the path is a symlink into a team repository — before anything is written, and goes in as an in-place edit, never a rewrite of the whole file
- **One procedure for saving a named version, `_common/version-pin.md`, used by `/fig:handoff` and `/fig:sync`.** Each had written the steps its own way, and sync's assumed a browser it was not allowed to call. Sync gains the browser tools; where none is connected, or the wrong account is signed in, the step is handed back with the exact name to use. The read-back after saving is told by the caller how to recognise its entry (handoff: `handoff.version.match`; sync: the exact title it saved), so sync no longer stops falsely for lack of a `match` key. Without a Figma token, sync reports that the entry could not be confirmed rather than asking for a link it has no use for, and a label with non-ASCII text is compared after normalising escapes, so a Korean or accented label that comes back escaped is not taken for a missing one
- **`/fig:handoff` writes in two steps, each behind its own preview and go: save the version, then write the line.** The version used to be saved before the preview, so the first write of the run happened unannounced. The preview now shows the line it will write, and a second run still leaves one heading
- **Every skill pre-approves the tools its body calls, and no others.** `/fig:lint` and `/fig:sync` no longer pre-approve reading Notion pages, and `/fig:draw` and `/fig:sketch` no longer pre-approve Figma's design-context read — none of the four used it. The other way round, the skills that call another skill, run a Figma script or a command, read a file or edit the config, and had to ask each time, are now allowed to: `/fig:arrows`, `/fig:prep`, `/fig:read`, `/fig:setup`, `/fig:sync` and `/fig:tokens`. An unattended run no longer stops on a prompt for a tool the skill needs, and none holds a wider grant than its job. The README's Notion row drops `/fig:lint` and `/fig:sync`
- **Every description is one sentence saying what the skill does and when, then its triggers.** What a skill does in detail is in its body already; the description is what decides whether it runs at all. A description over the length limit now **fails** `verify`, where it only warned
- **Three config keys are retired and nothing reads them: `annotation_category`, `scope_tags` (both only `/fig:diff`'s) and `sync.pair_patterns` (replaced by the direct comparison above).** They are out of `conventions.example.yaml` and the setup drafter no longer writes them. A config that still sets them is not an error — they are ignored — and can be deleted whenever convenient
- Wording: the example config's comments and `deck-base.js` name the measuring step of `/fig:deck` where they named `/fig:deck-setup`, and say that the version is saved through the web app rather than by hand. Every place that offers *Compare changes* says it needs a Dev Mode seat and compares a frame with its own history. `/fig:setup` no longer lists `/fig:handoff` among the skills that check the seat with `whoami`, since handoff's one Figma write goes through the web app. Both READMEs give `./deck-assets` as the deck assets default, with a shared folder as the option for a team sharing one template

## 3.27.0 — 2026-10-19

- **The audits skipped everything inside a section nested in another section.** `/fig:lint` walked only the page's top-level sections, so a frame sitting in a sub-section never reached the bounds, naming or overlap checks, and an arrow there never reached the flow checks. A whole nested block could read as clean because nothing in it was looked at. The three audit scripts now walk sections at every depth, composing each child's position through its parents. Section-name checks (number against placement, pattern) still apply to top-level sections only, since a sub-section is not numbered by the page's scheme
- **`[mode]` flagged correct screens inside nested sections.** Once sections were walked at every depth, a variable mode set on an outer section was no longer seen from a screen in an inner one, so a file set up the way the README advises (mode "somewhere above") was reported as rendering in the default mode, and `[mode]` is blocking, so `/fig:handoff` stopped. The check now looks at the screen, every section it sits in, and the page
- **An arrow's start could float in empty space and pass.** The start check measured to the nearest of the frame's four edges taken as infinite lines, so a point on an edge's extension, thousands of pixels outside the frame, counted as sitting on it. The distance is now measured to each edge as a segment. A point on or inside the frame reads the same as before
- **`/fig:arrows` re-sync kept the old arrow's style only on paper.** The skill said the existing stroke style, dashes and two-way heads were preserved, but the helper had no way to read them off the arrow being replaced, so a re-sync redrew everything in the config's style. New `styleOf(vector)` reads them before the old vector is deleted (colour, weight, dashes, opacity when it is not 1, and whether the arrow points both ways), and `arrow(...)` takes `opts.stroke` (`{color, weight, dash, opacity}`) to carry them over; where the old arrow has no solid stroke the config's style applies. The `[state]` lines go the same way: `stateLink(section, from, to, opts)` takes the same `opts.stroke`, and the skill's `[state]` sync step now reads the old line's style first instead of redrawing it in the config's
- **The shared scripts and the session hook identify their plugin by `plugin.json`, and the hook can no longer fail a session.** A checkout with a `pm/` directory in its path made `fig` read as `pm`, and the default config file name was a constant that came out wrong on the `pm` side; the scripts now read the `name` in the nearest `plugin.json` and fall back to the old path rule when there is none. The `SessionStart` hook exited with an error when PyYAML was missing, and the fetch could stall for the whole timeout when it asked for a credential or host key there is no terminal to answer. ## 3.19.0 — 2026-09-22

- **The cycle diagram had a step with no skill behind it.** Between `prep` and `arrows` it said "Draw the screens (official plugins, or by hand)" — the one step in the whole loop this bundle didn't actually do, so nothing carried the file's own conventions into it.
